## parp-tools WoW Viewer v0.4.7.1

.NET 10 / OpenGL 3.3 world viewer and debugging surface for WoW data from Alpha `0.5.3` through `4.0.0.11927`.

### Changes since v0.4.7

- Taxi route, node, actor-override, ride-camera, and route-recording controls are back in the active world-object inspector path instead of being stranded behind older navigation-only paths.
- Taxi actor transforms now derive facing from a smoothed route tangent, which reduces abrupt heading snaps and keeps the mount pointed along the path more like the real flight path behavior.
- Taxi ride camera now supports mouse freelook while attached to the moving actor, and direct ffmpeg-backed route capture now pads odd framebuffer sizes before H.264 output while surfacing encoder stderr when ffmpeg exits early.
- World-object targeting is now sticky across camera movement and streamed instance-list rebuilds, so selected WMOs and MDXs do not silently unselect just because the scene refreshed.
- Standalone WMO inspection now keeps groups loaded during camera movement and limits large in-scene labels to explicitly highlighted groups.
- The larger-range terrain and world-object follow-ups from the current train remain part of this snapshot: larger aerial detail budgets, improved distant-terrain support, and continued `wow-viewer` runtime seam extraction.

### Quick start

1. Extract the ZIP for your platform.
2. Run `ParpToolsWoWViewer`.
3. In-app, use `File > Open Game Folder (MPQ)` and select your client path.
4. Pick the client build in the build-selection dialog.
5. Load worlds from the left sidebar and use the right sidebar sections for `Inspect`, `Terrain`, `PM4`, `World`, and `Diagnostics`.

### Validation note

- The active viewer still has limited first-party automated regression coverage.
- This release reflects solution builds, packaging validation, and the currently checked-in viewer fixes, but the recent taxi, recording, selection, standalone-WMO, and larger-range terrain slices should still be treated as build-validated unless a narrower runtime note says otherwise in the memory-bank files.
