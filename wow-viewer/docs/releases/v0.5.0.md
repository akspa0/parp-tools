# parp-tools WoW Viewer v0.5.0

342 commits since v0.4.9. This is the largest release in the project's history — the viewer
was cut loose from its origins and rebuilt as an independent codebase.

## The headline: decoupled from MdxViewer

The viewer, its format libraries, and its CLI toolchain were **fully decoupled from the old
MdxViewer codebase** (`gillijimproject_refactor`) and re-established as the self-contained
`wow-viewer/` tree. This was a monumental refactor touching effectively every file:

- The application was renamed **MdxViewer → WoWViewer** and restructured into
  `src/viewer` (the app), `src/core` (shared format/domain/runtime libraries:
  `WowViewer.Core`, `.Core.IO`, `.Core.PM4`, `.Core.Runtime`, `.Core.Renderer`, `.Core.Anim`),
  and `tools/` (nine CLI tools: inspect, converter, harvest, capture, validation-capture,
  mask-validate, wdl-read, enrich, wmo-minimap).
- The old `gillijimproject_refactor` tree is now **read-only reference** — all live
  development happens in `wow-viewer/`.
- Obsolete library dependencies were removed outright: **MDX-L_Tool** (its functionality was
  natively ported to `Terrain/Transfer/M2ToMdxConverter.cs`), **WoWRollback**, and
  **WoWMapConverter.Core** are gone. The viewer now builds against a single copy of
  Warcraft.NET instead of two divergent checkouts.
- Vendored third-party libraries (SereniaBLPLib, DBCD, WoWDBDefs, wow-listfile, Warcraft.NET,
  WoWTools.Minimaps) are now **proper git submodules pinned to pristine upstream commits** —
  previously they were orphaned nested clones, invisible to any fresh checkout, two of them
  carrying unpushed local patches. Local patching of vendored code is eliminated; the one
  needed build accommodation (central-package-management opt-out) now lives in this repo's
  `Directory.Packages.props` where it belongs.

## CI, releases, and cross-platform builds

- **GitHub Actions CI from scratch** (`.github/workflows/wowviewer-build.yml`): every push
  builds the full solution on Windows, compile-checks the cross-platform target on Linux
  and macOS, and runs the test suite (informational). Tagged releases (`v*`) build and
  publish self-contained binaries for **win-x64, linux-x64, osx-arm64, and osx-x64**.
- **BLP texture decoding migrated from System.Drawing/GDI+ to ImageSharp** across all
  renderers, exporters, and CLI tools. GDI+ has been Windows-only since .NET 7 and threw
  `PlatformNotSupportedException` at runtime on Linux/macOS the moment any texture loaded —
  this was the real blocker to non-Windows builds, and it predates this codebase (the same
  calls existed in MdxViewer). With ImageSharp, the Linux/macOS builds are functional.
- Known limitation off-Windows: **native file-open/save dialogs are Windows-only** (the
  buttons no-op on Linux/macOS). Use the CLI automation flags (`--game-path`, `--build`,
  `--world`) to load content. Linux/macOS builds are new and lightly tested — report issues.
- Standing up CI immediately caught and fixed two long-standing repo-integrity bugs: an
  overbroad `.gitignore` rule silently hiding real C# source directories (9 files under
  `Maps/` had never been committed), and the orphaned-submodule situation above.

## Viewer fixes and cleanup

- **WMOv14 group names**: single-file (alpha) WMOs no longer show the wrong group's name
  (e.g. everything labeled "Cathedral of Light"). Each group's name is now taken from its
  own embedded name offset instead of being overwritten by a positionally-mismatched MOGI
  table entry. WMOv17 was never affected.
- **Status bar facing** was 180° off (looking North reported South) — fixed.
- **Status bar area names** now update in VLM-terrain sessions too; previously the AreaTable
  lookup only ran for the classic terrain manager even though coordinates displayed for both.
- Removed dead UI: the Model > LOD sidebar tab (a stub with no controls) and the
  "Cull WMO Backfaces (Experimental)" render-quality toggle (never safe to enable — WMO
  materials aren't reliably single-sided).

## Known issues

- **M2 rendering for client builds 0.11 through 2.4.3 does not work** — bounding boxes
  render, materials/mesh do not. This is the top known gap; investigation is planned
  (see the repo's memory bank for the current plan).
- Some test-suite entries fail without a locally staged game client or due to pre-existing
  test/implementation mismatches; these are documented in `memory-bank/progress.md` and do
  not affect the shipped binaries.

## Toolchain / data-pipeline highlights (same period)

- Spec 103 terrain-reconstruction lane: lean `V8LeanUNet` architecture (6.2M params,
  ~19× smaller than v7), curated V18 corpus, RunPod training deployment.
- Spec 097 full-map V18 → stitched mesh/WDL/ADT round-trip (slice 1 live).
- Numerous ADT/WDT/WDL/WMO format-handling improvements across the CLI tools.
