# parp-tools WoW Viewer v0.6.0-alpha2

**Alpha pre-release.** A fix-and-export pass on top of [v0.6.0-alpha](v0.6.0-alpha.md). The headline
items are a rendering regression fixed across every M2 era, LK ADT output that actually carries the
chunks the format requires, and the first-ever load of **DAT v22** terrain — plus a way to get that
data back out as client map files.

Items marked *not verified* below have not been seen working in a client. Please report what breaks.

---

## 1. M2 texture wrap fixed (all eras)

Cylindrical meshes — tree trunks, lighthouse tubes, anything whose UVs run past 1.0 around a
circumference — rendered with a smeared seam.

`M2Texture.flags` bit `0x1` is **"texture wrap X"** and `0x2` is **"texture wrap Y"**: the bit *set*
means repeat. The renderer was treating a set bit as *clamp*, so every texture that declared it must
wrap was clamped instead. Flat surfaces with UVs inside `[0,1]` looked identical either way, which is
why only tubes showed it.

Introduced 2026-09-12 while chasing smeared UVs on `ballistaruined.m2` and similar. That smearing had a
different cause — vertex-layout offsets reading UVs from the wrong place — which was fixed separately;
the inverted flag was never reverted.

> If wood/arrow/wheel models streak again, their UVs are genuinely out of range and the fault is
> upstream in UV reading for that era. It must not be "fixed" by re-inverting the flag.

## 2. LK ADT output now carries the chunks the format requires

`LkAdtWriter` is shared by 17 call sites — Alpha→LK conversion, split→LK, the Rosetta tileset
generator, the new-map creator, viewer map save — so this affects **every LK file the project has ever
written**, not just the new DAT export.

| Defect | Effect |
|---|---|
| `MCSE` never written | real LK tiles carry an empty sound-emitter chunk; ours had neither chunk nor offset |
| `ofsMCCV` (MCNK +0x74) never set | **MCCV was written where nothing could find it** — 179,200 orphaned chunks in one export |
| MCNK flag `0x40` never set | MCCV unannounced |
| `ofsMCLV` (+0x78) never set | same orphaning |
| `MHDR.ofsMFBO` hardcoded 0 | MFBO written but unreachable; flag `0x1` never set |
| `MTXF` never written | WotLK's per-texture flag table entirely absent |

Every MCNK header offset in the output has been verified to resolve to a chunk whose tag matches the
field (`MCVT`, `MCNR`, `MCLY`, `MCRF`, `MCAL`, `MCSH`, `MCSE`, `MCCV`), with the file walk closing
exactly on EOF. *Not verified: no output has been loaded in a 3.3.5 client or in Noggit.*

## 3. DAT v22 loads for the first time

All three DAT revisions — v22, v23, v26 — now load and render. v22 had never been seen before; the
sample is Burning Crusade Terokkar / Bone Wastes terrain.

v22 is structurally distinct from its siblings: no `ACVT`, no `AFBO`, it **omits empty `ACNK`**
(243–255 of 256, so never index chunks by ordinal), and it carries real **area IDs** and **live
shadows** where v26 has neither.

**Known gap:** v22 `AMAP` alpha maps use an unidentified encoding (128–3474 bytes, never 4096), so
**v22 renders layer 0 only**. Standard MCAL RLE is ruled out. A scoring oracle for cracking it is
confirmed to exist (`ACNK` +0x12 predominant-layer map, 0 violations across 997 chunks).

Also fixed: v22 objects loaded a **different random model on every run** — the adapter builds its
model-name table lazily while up to 4 tiles load on the thread pool, and handed out the live list.
Readers now get immutable snapshots.

## 4. Export a DAT map as LK or Alpha

**File → DAT Terrain (v22/23/26)** now groups every DAT action in one submenu, and there is a single
export button with the output format set by checkbox:

- **LK v18 ADT** — one `.adt` per tile plus the `.wdt`
- **Alpha 0.5.3 WDT** — a single monolithic `.wdt`

Tick either or both. The same control appears in the sidebar under World Overview when DAT terrain is
loaded. Every export writes a manifest naming each field carried and each field dropped, with a reason.

CLI equivalent:

```
adt-ahdr export-lk --root <folder> [--out <dir>] [--map <name>] [--format lk|alpha|lk+alpha] [--transpose]
```

Measured: v22 Expansion01 → 4 tiles / 999 chunks / 289 `MCSH` / 997 area ids / 849 placements;
v23 IcecrownCitadel → 3 tiles / 48 `MCAL` / 768 `MCCV`; v26 corpus → 699 tiles / 179,200 chunks /
8,457 `MCAL`.

> `--transpose` exists because the DAT grid's row axis runs along `ALOC` tile Y while the renderer's
> runs along its tile X, and nothing measured settles which way a standalone ADT should be written. If
> exported terrain comes out mirrored or rotated, that flag is the fix.

## 5. DAT folders as Cartography layers

A folder of DAT files can be added as a Cartography layer over a Standard-adapter base map — DAT files
are the terrain project files the shipped ADTs were built from, so this is a direct before/after of the
same ground. Its footprint draws on the minimap from the folder's own tiles, and the layer's offset,
cell-offset, rotation and mirror controls all apply.

*Not verified: no DAT layer has been composed on screen.* Standard base maps only; Alpha base maps
resolve donors differently and are not wired.

## 6. File picker fixed

Every file/folder picker in the application discarded a **pasted path** unless you pressed Enter or
clicked Go first — silently falling back to the process working directory. Confirming now commits the
typed path, or shows an error. This affected the CASC install picker, exports and overlays, not just
DAT.

## Known gaps

- v22 texture blending (`AMAP` codec unidentified) — layer 0 only.
- No exported map has been loaded in a client or Noggit.
- No DAT layer has been composed on screen.
- `MTXF` values are written as zeros; the chunk's presence and length are what readers need.
- There is still no modern (Cataclysm/MoP split) ADT writer: `MopSplitAdt` is a declared target with
  `HasWriter = false`, and the writer refuses it rather than mis-serialising.
- Captured minimaps for DAT folders are specified but not started.
