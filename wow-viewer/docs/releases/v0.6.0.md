# parp-tools WoW Viewer v0.6.0

**The first stable v0.6 release.** WoW: Forever (1.60) support has worked on every build since it landed, the
development map can be restored from PM4 collision and minimaps, and the viewer is now a stable base for
everything that follows. If you are one of the few people who wanted this, this one is for you.

> **Bring your own data.** parp-tools ships no game data. Point the viewer at your own client install,
> MPQ set, CASC install or extracted map folder.

---

## 1. What the viewer supports

| Client era | Support |
|---|---|
| Alpha 0.5.3 – 0.11 | **Complete** |
| 0.12 – 5.x | **Partial** (terrain, models and WMOs load; some era-specific features are missing) |
| WoW: Forever 1.60.1 (`wow_classic_beta`, CASC) | Stable — local install + optional CDN fill, 8 terrain layers, 64-bit holes, modern M2/WMO |

## 2. Restoring the development map

- **PM4 object restoration (partial):** PM4 collision meshes are matched to the objects Blizzard placed on the
  museum `development` tiles through a persistent association ledger (1,929 PM4 objects, 904 matched WMOs with
  bit-exact Z). Objects that the data supports now sit flush on their collision meshes with authentic rotation
  and no duplicates; huts and docks on tile `63_5` are the reference case.
- **Minimap-only terrain:** tiles that exist only as minimaps are baked into per-vertex colour (MCCV) so they
  render as coloured terrain instead of black.
- **Monolithic LK 3.3.5 output:** `inspect restore-unauthored` writes one `development_X_Y.adt` per tile,
  preserves every hand-authored tile byte-for-byte, and round-trip-verifies the result (616/616 tiles).
- **Known gap:** objects on tiles *adjacent* to PM4-covered tiles that exist in the museum data are still
  missing from restored tiles. This is the next item on the v0.6.1 line.

## 3. Archaeology tab — phase maps and map layering

- For the loaded base map the Archaeology tab lists the **phase maps** the client's DBC/DB2 tables define for it,
  when the client has them.
- If the client has none — or you want something else — **load any map on top of any other map**.
- See the user guide section "Archaeology: phase maps and map layering".

## 4. Fixes in this release

- Restored ADTs keep their original alpha maps (an 8-byte MCAL/MCSH offset shift in the shared reader had
  scrambled them; the restore tool now corrects it locally). Minimap colour baking no longer tints textured tiles.
- PM4 region grouping no longer counts empty regions as populated.

## 5. Experimental (not covered by the guide)

The dataset / ML research that rebuilds terrain from images alone (Zarr datasets, trestle/elevation models,
ComfyUI nodes) is **unexplored and unstable**. It lives under `data-harvester/` and needs your own data and GPU.
