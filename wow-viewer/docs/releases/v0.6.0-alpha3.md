# parp-tools WoW Viewer v0.6.0-alpha3

A performance release for **modern CASC clients — WoW: Forever** (`wow_classic_beta` 1.60.1). Exploring a
modern map used to sit at a few frames per second, hitch every frame while models streamed in, and leave
the minimap half-loaded. This release goes after each of those costs in turn, measured on the same spot
(Azeroth, Riverglades) after every step.

Items marked *not verified* below have not been confirmed on a real client. Please report what breaks.

---

## 1. Headline numbers

Operator captures on Azeroth (Riverglades), WoW: Forever 1.60.1, same camera spot:

| Measure | Start of this cycle | This release |
|---|---|---|
| Frame time (median) | 266 ms (≈ 4 FPS) | **77 ms (≈ 9–10 FPS), with 35 tiles loaded instead of 25** |
| Asset streaming stage per frame (median) | 68–98 ms | **7.6 ms** |
| Cost to create one M2 model | ≈ 55–65 ms | **≈ 0.1 ms** (textures no longer on the render thread) |
| Opaque M2 draws: instanced / one-by-one | 0 / 7,962 | **10,895 / 0** |
| Opaque M2 drawing | 24.8 ms | **8.3 ms** |
| WMO (building) drawing | 49 ms | **16.6 ms** |
| Minimap on CASC | tiles trickled in one per frame | **loads fully and quickly** |

The last measured bottleneck was M2 animation (≈ 44 ms). The animation rework in section 5 targets it
and has **not been measured yet** (*not verified*).

## 2. Textures: shared, streamed, compressed

- **Shared across models.** One texture used by 40 models was decoded and uploaded 40 times. Native M2
  models now share a reference-counted texture cache per data source.
- **Read and decoded off the render thread.** Worker threads read and decode; the render thread only
  uploads. A section draws once its texture arrives, so textures can appear a few frames after geometry.
- **DXT BLPs uploaded compressed** with the file's own mip levels, instead of CPU decode plus generated
  mips. Distant mips now come from the file (visible difference by design).
- **Missing textures bind the error texture** (`Textures\ShaneCube.blp`, else a magenta/black checker),
  as the client does, instead of probing ~135 guessed file names and scanning every `.blp` in the data
  source. Replaceable textures resolve from the client database only. Surfaces that used to get a guessed
  look-alike now show the error texture.

## 3. Faster model loading

- `.skin` lookup uses an index instead of scanning the whole `.skin` file list per model (same result;
  verified on 1,854 lookups).
- The M2 → MDX adapter parse is skipped when the native renderer is used (its output was discarded).
- **Models inside buildings (WMO doodads)** get all of the above too — they previously loaded through a
  separate path with none of it — and one copy of each doodad model is now shared by every building,
  instead of one per building. This removed the ≈ 70 ms-per-frame streaming hitch.

## 4. GPU instancing for native M2s

Every copy of the same model (the same tree ×200) is drawn with one instanced draw per section instead of
one draw per copy. The image should be identical: per-copy fade is applied in the shader exactly as the
per-copy path did. A/B switch: **Utilities → Perf → Frame history → Submission efficiency → "GPU
instancing for opaque models"**. *Visual A/B not yet reported.*

## 5. Animation rework (*not verified*)

- Animation key frames were decoded from raw file bytes on every sample, for every track of every bone,
  every frame. They are now decoded once per track and cached (identical values; unit-tested).
- Bone matrices are computed without allocating objects per bone (same math; unit-tested).
- **GPU skinning** for native models with up to 128 bones: the vertex shader applies the bone matrices
  instead of the CPU rebuilding and re-uploading every vertex every frame. Larger models keep the CPU path.

Aim: remove the stutter when walking from an area without animated models into one full of them.

## 6. Minimap on CASC

Decoded minimap tiles upload by time budget (up to 16 per frame, 32 with the minimap window open) instead
of one per frame.

## 7. Diagnostics

- Runtime Stats: per-phase model load times (read, skin lookup, parse, GPU create, WMO, WMO doodads), GC
  pauses, CASC cache/prefetch counters, streamed texture counters, shared doodad model counts.
- Perf panel: GC pause per frame, hitch attribution per stage.

## 8. Internals

- `WorldScene` split from 8,275 to 4,922 lines (Spec 255) and `ViewerApp` decomposed into services
  (U-01). Behavior-preserving.
- Perf panel code moved into its own service (it had been filed under the PM4 workbench).

## Known issues

- **Alpha 0.5.3 MDX models render overbright** (lighting/specular), including doodads. Reported for this
  build; the cause has not been identified yet. Nothing in this release's diff changes the MDX renderer or
  the lighting values it receives, so it may predate this cycle — a bisect is in progress.
- M2 animation cost after section 5 is not yet measured.
- WMO drawing (≈ 17 ms) and streamed texture uploads (≈ 2.6 ms each) are the next largest costs.
- Other retail CASC builds remain untested; only `wow_classic_beta` 1.60.1 is validated.
