# parp-tools WoW Viewer v0.6.0-alpha

**Alpha pre-release.** The v0.6 line is **modern data access + experimental terrain formats**. This
build carries forward the CASC install support and DAT v26 terrain reader from
[v0.5.4-alpha](v0.5.4-alpha.md) and completes the first pass over both: a game-version picker, the
full 8-layer terrain shader, modern WMO materials and LOD groups, decoded DAT v26 objects/normals/
colours, and an experimental DAT v26 writer. Harvest and the `inspect` CLI read CASC installs too.

Expect rough edges. Items marked *not yet* are known gaps.

---

## 1. CASC installs (local, with optional CDN fill)

- **File → Open CASC Install (local)...**: pick the folder that contains `.build.info`. Every product
  listed there is opened.
- **File → Open CASC Install (local + CDN fill)...**: files the install lists without having the data
  on disk are downloaded from Blizzard's CDN for the same build and cached under `output\cache\casc`.
- **Game version picker**: the open dialog lists the products in `.build.info` so you can pick the
  build to read instead of taking the newest. The newest is still the default.
- Built on [TACTSharp](https://github.com/wowdev/TACTSharp) (vendored as a submodule). File names come
  from the [community listfile](https://github.com/wowdev/wow-listfile); database layouts come from
  [WoWDBDefs](https://github.com/wowdev/WoWDBDefs), which includes `wow_classic_beta` 1.60.1.
- Tested against **WoW: Forever**, the `wow_classic_beta` product, build **1.60.1.69876** (a 12.0-based
  client).

## 2. FileDataID-era assets

- **Maps**: tile files come from the WDT `MAID` table; terrain texture names come from `MDID` (the
  files have no `MTEX`). Model placements flagged `0x40` (M2) and `0x8` (WMO) resolve by FileDataID.
  Map list, area names, lights and liquid types come from the build's own DB2 tables.
- **Terrain textures render up to 8 layers per chunk** (raised from 4). Each layer's alpha map is
  blended at full resolution from the tileset textures themselves.
- **M2 models**: chunked (`MD21`) models load on the native render path, with skins from `SFID` and
  textures from `TXID`.
- **WMO buildings**: roots without `MOTX`/`MODN`, groups from `GFID` (per-LOD groups resolved),
  material textures and doodads by FileDataID, modern per-shader base textures, and 16-bit `MOBA`
  material ids. A WMO that still fails to parse is skipped with a log line instead of crashing.
- Format-conformance pass against the wowdev.wiki audit is recorded in
  [spec 240](../../specs/archived/240-format-conformance/research.md).

## 3. DAT v26 terrain — first reader, renderer and writer anywhere

DAT v26 (the raw ADT project files that shipped in the `wow_classic_beta` build) is a **brand-new
terrain format** first analysed in this project on 2026-09-16. Format write-up:
[`docs/architecture/adt-v26-format.md`](../architecture/adt-v26-format.md); wowdev.wiki draft:
[`docs/wowdev-wiki/dat-v26.wiki`](../wowdev-wiki/dat-v26.wiki).

- **File → Open DAT v26 Terrain Folder...** opens a folder of DAT v26 files (any file names) and
  places each tile by its `ALOC` chunk. Heights, normals, vertex colours, texture layers and alpha
  maps render; `ACDO` object placements are decoded and placed.
- **Heights are inches**: the client's ADTs store yards, so DAT heights are 36× finer. The default
  display divisor is 36 (File → DAT v26 Height Scale). The corpus minimum −18,559.47 in ÷ 36 =
  −515.54 yd matches the shipped ocean floor.
- **Normals** come from `ANRM` (component order measured) and **vertex colours** from `ACVT`.
  Shadows (`ASHD`) are all zero in the corpus and are not rendered.
- **Experimental writer + export**: File → **Export Nearby Tiles as DAT v26 (experimental)** writes
  the ADT tiles within 2 tiles of the camera (terrain, texture layers, vertex colours, normals,
  objects) to `output/dat_v26_export`, which can be reopened with the DAT v26 folder command. The
  writer round-trips the 700-file v26 corpus byte-identically.
- *Not yet*: liquids, holes and area IDs — DAT v26 has no chunk or field for them in this corpus. DAT
  v26 is a format to **read and study**, not the project's save/interchange format
  ([spec 241](../../specs/archived/241-dat-v26-interchange/spec.md), deferred by the operator 2026-09-17).

## 4. CLI (`WowViewer.Tool.Inspect`)

- `casc products | read | exists | wmo | m2 | db2 | map-survey | adt-heights | bench` — open a local
  CASC install, resolve assets by FileDataID or listfile path, decode DB2, survey a map, export ADT
  outer-vertex heights, and benchmark reads.
- `adt-ahdr check` — decode a folder of DAT v26 files and verify tile seams.
- `adt-ahdr roundtrip` — decode and re-encode every file with the experimental writer; reports
  byte-identical files.
- `adt-ahdr objects` — resolve `ACDO` object placements and measure their heights against terrain.
- See [`docs/CLI-TOOLS.md`](../CLI-TOOLS.md#casc-installs-casc).

## 5. Harvest reads CASC installs

Every `wowviewer-harvest` `--client-root` command opens a CASC install when the folder (or its parent)
contains `.build.info`, and falls back to MPQ archives otherwise. FileDataID-era maps resolve their
tiles and textures through the same id-addressed reads as the viewer.

## 6. Fixes

- **Synthesized minimap export** now works for edited tiles and for CASC-backed worlds.

## Known limitations

- Chunks whose `MDID` layer entry is 0 in the shipped data have no texture.
- Height-based texture blending (`MHID`/`MTXP`) is not used by the terrain shader yet.
- The Azeroth WDT's `MAI2` chunk is not interpreted.
- DAT v26 exports have no liquid, hole or area data (the format carries none in this corpus).
- Remote-only CDN browsing without a local install is not in this build.
- CLI and harvest CASC reads are operator-testable but the wider asset matrix beyond
  `wow_classic_beta` 1.60.1 is unverified.
