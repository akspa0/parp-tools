# parp-tools WoW Viewer v0.5.2

Lighting corrections, synthesized-minimap time-of-day support, WMO overlay option, and UI cleanup.

## Project status

The viewer targets staged World of Warcraft client builds — Alpha 0.5.3, 0.6.0, LK 3.3.5, and
Cataclysm-era PM4 tiles — for format archaeology, terrain reconstruction, and dataset generation.
v0.5.2 is a maintenance release on the `v0.5.x` line: it fixes lighting bugs that degraded both
the 3D viewer and the synthesized-minimap pipeline, unlocks arbitrary time-of-day rendering, adds
an optional WMO overlay, and cleans up a broken taxi-panel popup. The synthesized-minimap feature
is the marquee capability — it composes terrain-only minimap PNGs directly from client BLP textures
plus MCLY/MCAL/MCNR/MCSH data, with a solar direction that matches the traced 0.5.3.3368 native
client behavior.

## Lighting fixes

- **Hillshade Y-axis inversion fixed** (`SynthesizedTrainingService.CalculateHillshade`): the
  image-space Y axis runs downward, but the standard hillshade formula assumes upward Y. The
  `lightY` component was not negated, so a configured 315° (north-west) azimuth rendered as
  south-west light — lighting the wrong faces of mountains in synthesized training pairs. The
  `SynthesizedTrainingService` is part of the retired VLM/MK dataset workflow; the fix keeps it
  correct for any remaining legacy consumption.
- **Object capture Z backlighting fixed** (`ObjectCaptureShader`): WoW 0.5.3 geometry uses DirectX
  winding (clockwise), but OpenGL defaults to counter-clockwise front faces, which inverts the
  effective Z component of normals. The hardcoded light direction with positive Z lit bottom
  surfaces instead of top surfaces — the "marshmallow" backlighting bug in object-library captures.
  The light direction is now a configurable `uLightDir` uniform, and the harvest tool sets its Z
  sign based on the client build (0.5.x negates, 0.6.0+ passes through).
- **Tone mapping always applied** (`ResolveSyntheticMinimapLighting`): the production minimap
  output now applies the Reinhard tone-map (exposure=20, calibrated 2026-07-20) at every time of
  day, not just noon. Without it the raw linear response was ~2.79× darker than authored minimaps.

## Synthesized minimap improvements

- **`--time-hours` restriction removed**: the `synthetic-minimap` command previously hard-locked
  the sun to 12:00 noon. It now accepts any time of day (formats `HHmm`, `HH:mm`, or decimal
  hours) and renders the corresponding solar direction. Default remains 12:00 (noon, full-bright),
  which matches the convention Blizzard uses for baked LOD minimaps in later clients.
- **Time-aware lighting**: uses `CreateWhiteTopEdge(gameTime)` (with tone mapping) instead of the
  hardcoded `CreateNoonWhiteGlobal()`, so the sun elevation follows the requested clock time.
- **Solar model**: the bearing stays fixed at north-west all day (matching the Ghidra-traced
  0.5.3.3368 `SetDirection` ray); only the elevation cycles. This is why time-of-day changes
  brightness/contrast, not the shadow direction.
- **`--bake-mcsh` flag**: bakes the terrain-side static shadow map (MCSH) into the RGB output.
  Without it, the output uses only Lambert hillshading (a 2D gradient, no cast shadows).
- **`--include-wmos` flag**: renders placed WMO geometry onto minimap tiles using the same solar
  lighting. Requires a headless OpenGL context. This option is a work-in-progress — the WMO
  compositing is experimental and defaults off in the GUI.

## Viewer UI fixes

- **Taxi panel pop-up removed**: the toolbar popup button and floating `DrawTaxiWindow()` were
  removed. The popup had no title bar and dismissed on any outside click, making route selection
  impossible. The workbench Utilities tab version is retained as the single entry point.
- **Synthesized minimap GUI**: added "Include WMO geometry" and "Bake MCSH shadows" checkboxes to
  the export dialog.

## Liquid compositing

- **Terrain-height gating** (`TerrainMinimapLiquidCompositor`): liquid pixels are now skipped when
  the liquid surface height is below the terrain surface at the same cell. WoW liquid data is a
  plane system, not cell-painted coverage — terrain can rise through a water plane, and without a
  height gate the liquid would float over the land. This affects WL*, MCLQ, and MH2O uniformly.

## Known issues

- The `--include-wmos` WMO overlay is experimental: it can fail or produce incorrect output on
  some clients/maps. It is disabled by default.
- The synthesized minimap does not render dynamic 3D cast shadows unless `--bake-mcsh` is enabled,
  and MCSH is a terrain-side static signal, not per-object shadows.
- **M2 rendering does not work for client builds 1.0.0 through 3.0.0** — bounding boxes render,
  materials/mesh do not. This is the known gap. Client builds 0.11 and 0.12 use the older MDX
  model type (not M2) and render correctly; builds 3.0.1 through 4.0.0 M2 render correctly.
