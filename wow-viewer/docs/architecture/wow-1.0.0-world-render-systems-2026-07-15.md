# WoW 1.0.0 World Render Systems — M2 / Terrain / Water / Blend — Implementation Guide (2026-07-15)

Companion to the lighting/shadow guide
([wow-1.0.0-world-lighting-shadow-model-2026-07-15.md](wow-viewer/docs/architecture/wow-1.0.0-world-lighting-shadow-model-2026-07-15.md)).
That doc covered **how the world is lit/shadowed/fogged**; this one covers **how the
geometry is actually drawn** — the M2/doodad batch pipeline, terrain surface, water, and
the blend-mode / render-state model — so the viewer can match the real surface look.

## 1. Frame / pass order (the master loop) **[V]**

`CWorldScene::Render` (`FUN_0067c460`):

1. Camera-in-WMO test → **interior portal walk** or **exterior pass**.
2. **Opaque world**: terrain → WMO opaque batches → opaque doodads (M2 pass 0).
3. **Fog select**: interior vs exterior fog params.
4. **Transparent / effects**: liquids → transparent doodads/WMO (M2 pass 1, back-to-front) → particles → ribbons.
5. **Shadows**: projected unit shadows / blobs.
6. Debug overlays.

The invariant: **opaque first (any order, depth-tested), transparent second (sorted
back-to-front, depth-test on / depth-write off)**. Water and additive effects live in the
transparent bucket.

## 2. M2 / doodad / creature render **[V]**

The world is full of M2 doodads — this pipeline is second only to terrain in visual weight.

### 2.1 Per-model tick — `FUN_006bf060`
- `alpha = (byte model+0xb) / 255` — the distance **fade-out** alpha (also used by `CWModelFadeout`).
- advance animation time by the real frame delta.
- build the sorted draw list (`FUN_00716c40`), then draw **pass 0 (opaque)** and **pass 1 (transparent)**.

### 2.2 Draw list & entry types — `FUN_00716c40` → `FUN_0071a150`
Each visible submesh/effect becomes a 0x38-byte render entry tagged by type:

| type | what | draw fn |
|------|------|---------|
| 0 | opaque geometry | `FUN_0071b550` |
| 1 | transparent geometry (distance-sorted) | `FUN_0071b970` |
| 2 | multi-region geometry (draws N sub-entries) | `FUN_0071bd30` |
| 3 | **particle** emitter | `FUN_0071c190` |
| 4 | **ribbon** emitter | `FUN_0071c220` |
| 5 | **projected shadow** | `FUN_0071c2d0` |

Transparent entries are sorted back-to-front by camera distance (`FUN_00721080`).

### 2.3 Per-batch material — the render flags **[V]**
Each batch references an M2 **renderFlag = `{ u8 flags, u16 blendingMode }`**:

- `flags & 0x01` = **UNLIT** — skip lighting, use the material/vertex color directly.
- `flags & 0x02` = **UNFOGGED** — skip fog.
- `flags & 0x04` = two-sided (disable backface cull) *[I, standard]*.
- `flags & 0x08` / `0x10` = depth-test / depth-write off *[I, standard]*.
- **`blendingMode`** (0–6), map to fixed-function blend:

| mode | name | glBlendFunc (src, dst) | use |
|------|------|------------------------|-----|
| 0 | Opaque | disable blend | solid |
| 1 | AlphaKey | alpha-test ≈0.5, no blend | cutout (leaves, grates) |
| 2 | Alpha | `SRC_ALPHA, ONE_MINUS_SRC_ALPHA` | glass, decals |
| 3 | Add | `SRC_ALPHA, ONE` | glows, fire |
| 4 | Add (alpha) | `SRC_ALPHA, ONE` (no vtx-α mod) | glows |
| 5 | Mod | `DST_COLOR, ZERO` | shadows/darken |
| 6 | Mod2x | `DST_COLOR, SRC_COLOR` | detail/overlay |

Material **color + alpha are animated** (from the M2 color/transparency tracks) and sampled
per frame (`FUN_0071ae30`); emissive folds into base when unlit.

### 2.4 Textures — `FUN_0071a540` **[V]**
- **Max 2 textures per batch** (asserted `textureCount < 2`... i.e. ≤2). Second unit = env-map
  or detail/overlay.
- Each unit has an optional **animated UV transform** (the M2 texture-transform track) — scrolling
  water-in-cauldron, spinning runes, etc. Apply the per-unit texture matrix.

### 2.5 Renderer action (M2)
- Build a per-submesh batch with: 1–2 textures (+ animated UV matrices), a renderFlag
  (`unlit`/`unfogged`/`cull`/`blendMode`), and an animated `color·alpha`.
- Two passes: opaque (depth write on), then transparent (sorted back-to-front, depth write off),
  each applying the blend table above.
- Fade distant doodads with the model alpha (`CWModelFadeout`).
- Particles/ribbons/projected shadows are separate entry types — stub them first, add later.

## 3. Terrain surface **[V]**

### 3.1 Vertex format — `FUN_006c0db0`
Terrain VBO = **24 bytes/vertex = `position` (3f) + `normal` (3f)**. No color, no UV in the
stream. **This resolves the open question from the lighting doc: terrain is hardware
FFP-lit** — the MCNR normal is uploaded and `GL_LIGHT0` (sun) + ambient compute `N·L` on the
GPU. UVs are generated by planar tiling of the layer textures over the chunk.

### 3.2 Texture layers & draw
- Up to **4 MCLY layers**: layer 0 opaque base, 1–3 alpha-blended by the **MCAL** alpha maps,
  composited by FFP multitexture / register combiners.
- Draw = one indexed **LOD triangle-strip** with neighbour-aware seam stitching
  (`FUN_006c65c0`), index count from a per-LOD table (`FUN_006c0e80`).
- **MCSH** 64×64 1-bit shadow map → `shadowGxTexture`, multiplied over the lit terrain (see
  lighting doc §3.4).

### 3.3 Renderer action (terrain)
Light per-pixel from the interpolated MCNR normal (`ambient + sun·N·L`), multiply the MCSH
shadow, blend the 4 MCLY layers by MCAL alpha, apply distance fog. (Same as lighting-doc P0/P1.)

## 4. Liquid / water **[V]**

### 4.1 Types & textures
- **12 liquid types** (`LIQUID_COUNT=0xC`, `LIQUID_NONE`). `liquidTexBaseName[type]` @
  `0x00834d4c`: `river\lake_a`, `river\fast_a`, `ocean\ocean_h`, `slime\slime`, + lava / splash / water.
- Textures are **flipbook-animated**: `XTextures\<type>\<name>.%d.blp`, ~**30 frames/type**
  cycled over time (`FUN_00686d40`). Water is a scrolling/flipbook tiling texture, not a shader sim.

### 4.2 Geometry & shading
- Liquid = an **8×8 tile grid per map-chunk** (`MD_LIQUID_NPOLY=8`); each tile has a type nibble
  + a **depth** value. Depth drives the surface Z and the **shore alpha fade** (shallow → transparent).
- Terrain liquid = **MCLQ** chunk; WMO-internal liquid = **MLIQ** (wmo doc §20.5: xVerts·yVerts
  vertex grid + tile flags).
- Shaders: `ocean0_s.bls` (terrain deep water), `MapObjExtWater0.bls` (WMO near water). Ripple:
  `Water0Ripple` / `WaterRadWave`. Cvars: `waterRipples/Specular/Waves/Particulates/MaxLOD/LOD`.
- Drawn in the **transparent bucket** after opaque terrain/WMO: alpha-blended animated texture,
  optional specular highlight, depth-based shore transparency.

### 4.3 Renderer action (water)
Build the liquid surface from the tile grid (type + depth per tile); animate the texture by
cycling frame `= (time * fps) % 30`; alpha-blend with shore fade from depth; add a simple ripple
normal/scroll. Start with water/ocean/lava/slime; the 12-type table just selects the texture set.

## 5. Render state model (CGx / CGxStateBom) **[V]**

- All lighting/fog/material/blend is **fixed-function state**, set through a batched state stack
  (`CGxStateBom`): push-token (`FUN_0058cb30`), set-texture (`FUN_0058cae0`), set-color
  (`FUN_0058ca90`), begin/end pass (`FUN_0058ccb0/ccc0`), draw (`FUN_0058dd90`). Changes are
  queued and flushed together to cut GL/D3D call overhead.
- The `.bls` pixel shaders (NV register combiners / ARB fp / D3D ps_1_1–2_0) only implement the
  **multi-texture combine** stage — they are not where lighting/blend live.
- **You do not need to reproduce CGxStateBom.** A modern renderer sets blend/depth/cull per batch
  directly (or sorts by state). The value here is knowing the *set* of states that matter:
  blendMode, alpha-test, cull, depth-test/write, up-to-2 textures, texture matrix, fog on/off,
  lighting on/off, material color+alpha.

## 6. Consolidated gap list (adds to the lighting doc's P0–P3)

| System | 1.0.0 reality | Note |
|--------|---------------|------|
| M2 blend modes | 7-mode enum (opaque/alphakey/alpha/add/add/mod/mod2x) + unlit/unfogged/cull flags | **do this** — wrong blend = wrong doodad look |
| M2 2-tex + animated UV | ≤2 textures/batch, per-unit texture matrix from anim tracks | scrolling/spinning effects |
| Transparent sort | back-to-front per-model distance sort | correct alpha layering |
| Terrain FFP lighting | normals in VBO → `N·L` on GPU (confirmed, not a bake) | matches lighting-doc P0 |
| Water flipbook | animated `%d.blp` (~30 frames) + depth shore fade + tile grid | animated water surface |
| Particles / ribbons / projected shadows | separate M2 entry types (3/4/5) | later; stub first |

**Build order stays:** lighting-doc P0/P1 (normal-lit terrain + day/night + MCSH + fog) first —
then M2 **blend modes + 2-tex + transparent sort** (this doc §2) — then **animated water** (§4) —
then particles/ribbons.
