# Feature Specification: Image-Only Generative Terrain Reconstruction (WDL Height PoC)

**Feature Branch**: `103-image-only-reconstruction`

**Created**: 2026-07-13

**Status**: Draft

**Input**: Reconstruct terrain from a single image tile alone. No auxiliary signals exist for real use-case data, so every signal must be generated from the image, and validation must not depend on ground-truth signals we will never have.

## Governing Principle (the design law) *(mandatory)*

This law outranks every design choice in this spec and supersedes any conflicting assumption in Spec 102.

1. **The only deployment input is one image tile.** A minimap tile, or in the limit any image. No object mask, height, WDL, normals, liquid, or any other signal exists for the data we actually want to reconstruct.
2. **Every other signal is generated from the image.** The model stack manufactures each missing signal from pixels alone (plus signals generated by upstream models). There is no such thing as a "provided" auxiliary signal at deployment.
3. **No model may consume a ground-truth signal at inference.** Ground-truth signals from game clients exist for exactly two purposes: to supervise training and to compute development diagnostics. They never enter any model's forward pass, initialization, teacher-forcing route, feature cache, normalization anchor, or post-processing at inference.
4. **Downstream models train on generated upstream outputs, not ground truth.** If a stage will consume an upstream signal at inference, it must be trained on that upstream model's generated (imperfect) output, so training and deployment match.
5. **A target the image cannot support is invalid.** A supervised target must contain only information derivable from the input image. Labels that encode what the image does not show (e.g., objects buried under terrain) are impossible targets and must be corrected or dropped, not learned.

## Problem & Proof of Concept

The proof of concept is the core generative loop, nothing more: **one minimap image tile → the WDL height lattice** (paired 17×17 outer + 16×16 inner samples). Trained directly ("gung-ho"), image-only.

Objects in the minimap locally poison the height output (buildings and structures read as height bumps). **This is accepted noise for the PoC.** Perfecting object handling is explicitly not a prerequisite. Object masking is a later, optional refinement and is cheaper as an output-space cleanup (mask artifacts in the generated output) than as an input requirement.

This spec exists to take the Spec 102 tangle — the strict fragment-trace sidecar, the precise-mask target that included invisible under-terrain objects, and validation that leaned on ground-truth signals — and make it tidy under the single principle above.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Height from a single image (Priority: P1)

Given one minimap image tile and nothing else, the system generates the WDL height lattice for that tile.

**Why this priority**: This is the proof of concept. It proves the core claim — regenerate terrain height from a single image — and unblocks the rest of the program.

**Independent Test**: Feed a minimap image with every other signal made unavailable; receive a complete WDL height lattice. On held-out game tiles, the ground-truth lattice may be compared as a development diagnostic only.

**Acceptance Scenarios**:

1. **Given** a single minimap tile with no auxiliary signals, **When** inference runs, **Then** a full paired WDL height lattice is produced without reading any other signal.
2. **Given** a minimap tile containing visible objects, **When** inference runs, **Then** height is still produced; object-induced local error is tolerated and reported, not treated as failure.

### User Story 2 - Label-free, use-case-faithful validation (Priority: P1)

The model is judged the way it will actually be used: image-only inputs that have no ground-truth signals, scored by whether the generated output is self-consistent.

**Why this priority**: A validation that requires the ground-truth signal can only ever run on game data where we already have the answer. It cannot test the real use case, so it cannot be the product's acceptance criterion.

**Independent Test**: Run image-only inference on tiles (including at least one out-of-distribution image) with no labels available, and evaluate the output by self-consistency: adjacent-tile shared-border agreement, physically plausible height range and gradients, and absence of seams or artifacts.

**Acceptance Scenarios**:

1. **Given** held-out tiles with no ground-truth signals, **When** they are reconstructed and stitched, **Then** shared borders agree within the registered threshold and no seam artifacts appear.
2. **Given** any label-free input, **When** it is reconstructed, **Then** the height field is finite, within a plausible range, and free of checkerboard/blocky artifacts.

### User Story 3 - Optional object cleanup by output-space segmentation + inpaint (Priority: P3)

Later and optionally, object artifacts are removed from the *generated output* by image segmentation — not by requiring an object signal at input. Because the generated WDL lattice is a coarse, downscaled representation of the physical terrain, the segmented-out object regions can be inpainted from the surrounding height, or hand-manipulated in a second pass.

**Why this priority**: Nice-to-have and deliberately fast-and-dirty. Objects are accepted noise for the PoC. Segmenting them out of the output and inpainting is cheaper and more controllable than perfecting an input mask, and it leaves the result editable.

**Independent Test**: Run segmentation on a generated height field, mask the object-artifact regions, inpaint them from the surrounding lattice, and show reduced artifacts with the input contract unchanged (still image-only).

**Acceptance Scenarios**:

1. **Given** a generated height field with object bumps, **When** output-space segmentation masks them and the holes are inpainted from neighbors, **Then** object artifacts are reduced, the terrain stays continuous, and the input contract is unchanged (still image-only).
2. **Given** a cleaned output, **When** a user manipulates or re-inpaints a region in a second pass, **Then** the edit is local and requires no additional input signal.

### Edge Cases

- **Input with no terrain at all** (e.g., an arbitrary photo): the model still runs image-only and produces *some* height field; it is judged by self-consistency, not correctness, since no ground truth exists.
- **Blank / dead-space tiles** (all-holes minimap art): excluded from training as noise, since the input carries no usable signal.
- **Objects dominating a tile** (dense city): height error is expected to be higher; recorded as a diagnostic, not a gate.
- **Tile borders**: reconstructed independently, they must still agree at shared edges — the primary label-free check.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: The deployed model MUST take exactly one image tile as input and MUST NOT require any other signal at inference.
- **FR-002**: Every non-image signal MUST be generated by the model stack from the image (and generated upstream signals); no ground-truth signal may enter any model's forward pass at inference.
- **FR-003**: A downstream model that consumes an upstream signal MUST be trained on the upstream model's generated output, not on ground truth.
- **FR-004**: The PoC learned target MUST be the WDL height lattice; object masking MUST NOT be a prerequisite for the PoC.
- **FR-005**: The WDL target MUST be the real paired lattice (outer 17×17 at stride 16, inner 16×16 at offset 8 stride 16). The invalid `wdl_height_33 = height_257[::8]` raster MUST NOT be used as a target, gate, or export.
- **FR-006**: Validation MUST be label-free and use-case faithful: image-only inference judged by self-consistency (adjacent-tile border agreement, plausible height range/gradients, absence of seams/artifacts) on inputs without ground-truth signals.
- **FR-007**: Ground-truth-label metrics (height error, IoU, etc.) are development-only diagnostics on the labeled game subset. They MUST NOT be the product acceptance criterion or presented as validation of the use case.
- **FR-008**: Held-out validation MUST hold out complete maps (and ideally a build/era) so diagnostics are not memorization.
- **FR-009**: Object handling is optional and deferred, and MUST operate in output space — segment object artifacts in the generated output, mask them, and inpaint from the surrounding lattice — never as an added input requirement. The cleaned output MUST remain editable (a second manipulation/inpaint pass is a supported use), which is feasible because the WDL lattice is a coarse downscaled representation of the physical terrain.
- **FR-010**: The Spec 102 strict fragment-trace sidecar and precise-mask target are NOT PoC prerequisites; they are retained only as optional later refinements and MUST NOT block the WDL PoC.
- **FR-011**: Every training run MUST record command, data identity, split, per-epoch metrics, and peak VRAM, and MUST NOT be claimed as success without passing the label-free acceptance check.
- **FR-012**: A training store MUST pair the minimap image with the real WDL lattice per tile. The current 3-array precise-mask store lacks height/WDL, so a suitable store MUST be produced or identified before training.
- **FR-013**: The training corpus MUST be curated before use, not consumed raw. Tiles whose supervised height target is not supportable by the image — object-contaminated tiles (Principle #5), blank-minimap dead space, and height/normal-mismatch harvest failures — MUST be dropped, and the kept set recorded in an auditable curation manifest bound to the store. Object tile removal is the default (`--max-object-coverage 0.0` drops ANY object), not an opt-in; the manifest MUST record per-tile drop reasons and the thresholds used.

### Key Entities

- **Input image tile**: minimap RGB (256×256). The only deployment input. Everything else is generated from it.
- **WDL height lattice**: paired 17×17 outer + 16×16 inner samples (545 values). The PoC output signal, generated from the image.
- **Generated signal stack**: every non-image signal, produced by models; never assumed present.
- **Ground-truth game signals**: height/WDL/mask from game clients; supervision and dev diagnostics only, never an input or the acceptance test.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: From a single minimap image with all other signals unavailable, the system produces a complete WDL height lattice (image-only inference proven).
- **SC-002**: On held-out complete maps, reconstructed adjacent tiles agree at shared borders within the registered threshold, with no seam artifacts — measured without any ground-truth label.
- **SC-003**: The end-to-end loop (image → lattice) runs on inputs with zero auxiliary signals, including at least one input outside the training distribution.
- **SC-004** *(dev diagnostic, not acceptance)*: On the labeled game subset, generated height beats the trivial flat/mean baseline by a recorded margin — reported explicitly as a development metric, not the product proof.
- **SC-005**: An audit confirms no model in the pipeline reads a ground-truth signal at inference.

## Assumptions

- Minimap RGB tiles are the only guaranteed deployment artifact; real target data carries no auxiliary signals.
- Game-client training tiles carry ground-truth height/WDL for supervision; this is training-time only.
- Objects locally degrade the height output; this is acceptable for the PoC and addressed later in output space.
- The generated WDL lattice is a coarse, downscaled representation of the physical terrain, so object-artifact regions removed by segmentation can be plausibly inpainted from neighboring samples and edited in a second pass.
- A store pairing minimap + real WDL lattice is available or will be built; the current precise-mask store (minimap + object mask + liquid only) does not contain height/WDL.
- Spec 102 numeric/height contracts (raw MCVT vertices, paired WDL definition) remain the source of truth for what the real WDL lattice is.
