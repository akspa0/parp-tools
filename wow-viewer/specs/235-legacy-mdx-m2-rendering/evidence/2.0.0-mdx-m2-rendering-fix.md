# Evidence Receipt: 2.0.0 .mdx to .m2 Model Rendering & Vertex Layout Fix

- **Date**: 2026-09-12
- **Branch**: `235-legacy-mdx-m2-rendering`
- **Related Spec**: `specs/235-legacy-mdx-m2-rendering/spec.md`
- **Issues Addressed**:
  1. In 2.0.0 client (`H:\CLIENTS\TBC\2.X_Pre-Release_Windows_enUS_2.0.0.5610\World of Warcraft`) on maps such as `Expansion01.wdt`, doodad placements referencing `.mdx` files (such as `wallshield03.mdx`) were not rendered, rendering only yellow wireframe bounding-box fallback boxes.
  2. When `.mdx` doodad references successfully resolved and loaded (e.g., `hellfire_oldorcbanner02.mdx`), textures appeared distorted, flat brown, or misaligned due to scrambled UV coordinates and normals.

---

## 1. Root Cause Analysis

### 1.1 Format Profile Version Rejection
- `FormatProfileRegistry.cs`: `M2Profile20xUnknown` hardcoded `MinSupportedVersion = 0x104`.
- In 2.0.0 pre-release (`2.0.0.5610`), MD20 models declare version `0x100`.
- When `WorldAssetManager.LoadMdxModel` loaded `wallshield03.m2`, `WarcraftNetM2Adapter.ValidateModelProfile` threw:
  `InvalidDataException: Model 'wallshield03.m2' is incompatible with M2Profile_20x_Unknown (build=2.0.0.5610): MD20 version 0x100 is outside supported range 0x104-0x107.`
- This caused `LoadMdxModel` to catch the exception and return `null`, which triggered the bounding-box wireframe fallback.

### 1.2 Canonical Model Path Resolution
- `WorldAssetManager.ResolveCanonicalModelPath(normalizedKey)` and `WmoRenderer.ResolveCanonicalDoodadPath` only probed `TryResolveFromFileSet`, which queried the listfile (`_canonicalPathMap`).
- If the listfile did not list the `.m2` variant, `ResolveCanonicalModelPath` returned `normalizedKey` (`.mdx`) without checking `_dataSource.FileExists(alternatePath)` (unlike `ViewerApp.ResolveStandaloneCanonicalModelPath` which does check `FileExists`).
- In `WorldAssetManager.LoadMdxModel`, when `ReadFileData` resolved via an alternate path cached in `_resolvedReadPathCache`, `resolvedModelPath` was not updated to the actual resolved path, leaving it pointing to `.mdx` for downstream skin and texture lookups.

### 1.3 M2Era100 Vertex Layout Inversion (UV / Normal / Bone Weight Corruption)
- In `M2Era100Constants.cs`, the 48-byte `M2Vertex` layout internal offsets were incorrectly defined:
  - `VertexNormalOffset` was `0x0C` (actually bone weights and indices).
  - `VertexTexCoords0Offset` was `0x18` (actually `normal.Y` and `normal.Z`!).
  - `VertexTexCoords1Offset` was `0x20` (actually `UV0`).
  - `VertexBoneWeightsOffset` was `0x28` (actually `UV1.X`).
  - `VertexBoneIndicesOffset` was `0x2C` (actually `UV1.Y`).
- As a result:
  - UV coordinates received the Y and Z coordinates of the normal vector, resulting in completely scrambled texture coordinates (flat brown or stretched colors).
  - Normals were parsed from raw bone weights and indices, producing invalid normal vectors.
  - Bone weights were parsed from UV1.

## 2. Files Changed

1. [FormatProfileRegistry.cs](file:///I:/parp/parp-tools/wow-viewer/src/viewer/WoWViewer/Terrain/FormatProfileRegistry.cs):
   - Changed `M2Profile20xUnknown.MinSupportedVersion` from `0x104` to `0x100` to allow 2.0.0 `0x100` MD20 models to validate.
2. [WorldAssetManager.cs](file:///I:/parp/parp-tools/wow-viewer/src/viewer/WoWViewer/Terrain/WorldAssetManager.cs):
   - In `ResolveCanonicalModelPath`: Added `_dataSource.FileExists` check on `normalizedKey` and alternate paths (`.m2`, `.mdl`) when listfile resolution misses.
   - In `LoadMdxModel`: When model bytes are successfully read, updated `resolvedModelPath` from `_resolvedReadPathCache` so skin search and renderer construction operate on the true resolved path.
3. [WmoRenderer.cs](file:///I:/parp/parp-tools/wow-viewer/src/viewer/WoWViewer/Rendering/WmoRenderer.cs):
   - In `ResolveCanonicalDoodadPath`: Added `_dataSource.FileExists` probe on alternate paths when listfile resolution does not find an alternate extension.
4. [M2Era100Constants.cs](file:///I:/parp/parp-tools/wow-viewer/src/core/WowViewer.Core.IO/M2Era100/M2Era100Constants.cs):
   - Fixed `M2Vertex` internal layout offsets to standard WoW M2 binary specification:
     - `VertexPositionOffset = 0x00` (12 B: C3Vector)
     - `VertexBoneWeightsOffset = 0x0C` (4 B: uint8[4])
     - `VertexBoneIndicesOffset = 0x10` (4 B: uint8[4])
     - `VertexNormalOffset = 0x14` (12 B: C3Vector)
     - `VertexTexCoords0Offset = 0x20` (8 B: C2Vector)
     - `VertexTexCoords1Offset = 0x28` (8 B: C2Vector)
5. [M2Era100ModelReaderTests.cs](file:///I:/parp/parp-tools/wow-viewer/tests/WowViewer.Core.Tests/M2Era100ModelReaderTests.cs):
   - Added unit test `Era100Reader_ReadsVertexAttributes_WithStandardM2LayoutOffsets` verifying correct extraction of position, normal, UV0, UV1, and bone weights/indices.
   - Updated `CreateSyntheticEra100M2` and added `WriteVector2` helper.
