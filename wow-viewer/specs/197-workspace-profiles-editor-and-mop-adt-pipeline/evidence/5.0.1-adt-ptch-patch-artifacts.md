# 5.0.1 ADT PTCH/BSDIFF patch artifacts — native reconstruction contract

## Question

Why do random tiles/chunks go missing in the viewer for MoP 5.0.1 maps (Thunder Isle /
`HawaiiMainLand`) while liquids, object placements, and some terrain render fine?

## Answer

Loose `.adt` files extracted from the 5.0.1 MPQ data are frequently **PTCH/BSDIFF patch
artifacts** (`PTCH` / `MD5_` / `BSD0` / `BSDIFF40` bytes) rather than reconstructed ADT
streams (`REVM` / `RDHM` / `KNCM`). The native client never parses these bytes directly:
its resource layer hands `MapArea` **already-reconstructed** file data. The viewer had no
reconstruction step, so artifact bytes reached `ParseAdt`, the chunk scan found no valid
`KNCM` records, and the tile silently produced zero chunks — matching the "random missing
tiles" symptom exactly (unpatched tiles parse fine; patched ones vanish).

## Native evidence (Ghidra, Wow.exe 5.0.1.15464, base 0x00400000)

| Function | Role | Finding |
|---|---|---|
| `FUN_00BB0850` | `MapArea` ADT file-data registration (`MapArea.cpp:199-200`) | Stores up to 3 ADT file-data objects; builds packed key via `FUN_00BB6C70`; delegates acquisition to `FUN_00BB7D10`. |
| `FUN_00BB6C70` | Cache key builder | `mapId(16b) << 4 \| adtFileType(4b) << 6 \| y(6b) << 6 \| x(6b)`; asserts `x < 64`, `y < 64`, `adtFileType < 0x10`, `mapId < 0x10000`. |
| `FUN_00BB7D10` | Keyed resource acquire | Hash-table lookup (`FUN_00BB71B0`) or create (`FUN_00BB7C80`) + register with resource manager `FUN_005A7750` (callbacks `FUN_00BB6B30`, `FUN_00BB70F0`, `FUN_00BB6B70`, `FUN_00BB6C30`). |
| `FUN_00BB71B0` | Hash-table lookup | Pure bucket walk (`mask`, `index < array size` asserts). No file I/O, no patch logic. |
| `FUN_00BB7C80` | Bucket entry create | Pure vtable-dispatch allocation. No file I/O. |
| `FUN_00BB6B30` | Destroy callback | `MapAdtFileData.cpp:0x3c` → `FUN_00B69620` (`MapMem.cpp:0x204` free). |
| `FUN_00BB70F0` | **Load-complete callback** | `MapAdtFileData.cpp:0x44-0x4c`: stores `(fileData, size)` into `m_fileData`/`m_fileDataSize`; asserts data non-null and size > 0. The bytes it receives are final reconstructed file content. |

Conclusion: by the time `MapArea` registers an ADT file-data object, the MPQ/resource layer
has already resolved the patch chain. The client never feeds `PTCH` bytes to the ADT parser.

## Artifact format (observed in loose 5.0.1 files)

```
'PTCH'                      ; magic
<int32>                     ; header size (not load-bearing for parsing)
'MD5_'                      ; base-hash marker
<16 bytes>                  ; MD5 of the base (pre-patch) file
'BSD0'                      ; patch marker
<int32 LE>                  ; BSDIFF payload size
<BSDIFF40 payload>          ; standard bsdiff: 'BSDIFF40' + 3×int64 BE block sizes
                            ; (control, diff, newSize) + BZip2(control) + BZip2(diff) + BZip2(extra)
```

Reconstruction = find the base copy whose MD5 matches the embedded hash, apply the BSDIFF
delta, and require the result to start with on-disk reversed `REVM`.

## Viewer implementation (this change)

- [`AdtPatchArtifact.cs`](../../../src/core/WowViewer.Core.IO/Maps/AdtPatchArtifact.cs) — pure
  PTCH parse + BSDIFF40 applier + MD5-matched base selection (`TryReconstruct`), no I/O.
- [`IArchiveReader.cs`](../../../src/core/WowViewer.Core.IO/Files/IArchiveReader.cs) — new
  default `IArchiveCatalog.ReadFileCopiesLowestFirst` (base archives before patch archives).
- [`IDataSource.cs`](../../../src/viewer/WoWViewer/DataSources/IDataSource.cs) — new default
  `ReadFileCopies` (single-copy fallback for simple sources).
- [`MpqDataSource.cs`](../../../src/viewer/WoWViewer/DataSources/MpqDataSource.cs) — override
  enumerating archive copies (lowest priority first), alpha-wrapper copy, then loose copy.
- [`StandardTerrainAdapter.cs`](../../../src/viewer/WoWViewer/Terrain/StandardTerrainAdapter.cs) —
  `LoadMapTile` reconstructs root + `_texN` + `_objN` companions when they start with `PTCH`;
  on failure logs an Important diagnostic and treats the file as missing instead of feeding
  artifact bytes to `ParseAdt`.

Regression coverage: [`AdtPatchArtifactTests.cs`](../../../tests/WowViewer.Core.Tests/AdtPatchArtifactTests.cs)
(7 tests: magic detection, MD5-matched reconstruction, no-base failure, artifact-candidate
skipping, insert/seek BSDIFF runs, bad-magic rejection).

## Known limitations

- Multi-step patch chains (patch → patch-2 → …) are resolved only when each intermediate base
  copy is present as a candidate; the MD5 match makes selection order-independent, but a
  missing intermediate base fails reconstruction with a clear log line.
- The WDT itself is read before adapter construction and is not PTCH-reconstructed in this
  change; extend the same helper if a patched WDT is observed.
- `TryGetPlacementSourceData` (editor write path) still reads raw companion bytes; editing
  patched companions is out of scope.
