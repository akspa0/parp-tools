## 2. Primitives added to `SharedUiWidgets`

All new members are additive; the existing API is unchanged, so other services still compile.

| Primitive | Purpose | Token source |
|---|---|---|
| `ButtonSpec` (readonly record struct) + `Btn(label, action, enabled, help, small)` | One button of a row. | — |
| `DrawButtonRow(params ButtonSpec[])` | A row of action buttons; 8 px spacing, per-button disabled state, per-button help tooltip. | `UiTokens.Space8` |
| `SectionTitle(string title)` | A **non-collapsible** section title (the shared home for section headings that only group content). | token item spacing (`Space8`/`Space4`) |
| `BodyText(string, bool muted)` / `BodyTextWrapped(string, bool muted)` | Body copy in the shared body colours. The wrapped variant uses `PushTextWrapPos(0)` + `TextUnformatted`, so data containing `%` is never parsed as a format string. | `UiTokens.Text`, `UiTokens.TextMuted` |
| `SuccessText(string)` | "It worked" status line. | `UiTokens.Success` |
| `MutedSelectable(label, selected, flags, size)` | A selectable row in the muted colour. | `UiTokens.TextMuted` |
| `DrawEmptyState(title, message, actionLabel?, action?, help?)` | **Explicit empty state**: what is missing, plus the action that fixes it when the panel owns one. | `UiTokens.Text` / `UiTokens.TextMuted` |
| `PushSurfaceStyle()` / `PopSurfaceStyle()` | The shared window surface: background, border, rounding, padding. | `UiTokens.Surface1`, `UiTokens.Border`, `UiTokens.WindowRounding`, `UiTokens.WindowBorderSize`, `UiTokens.WindowPadding` |

`UiTokens` is `internal` in `WoWViewer`; `SharedUiWidgets` only uses it inside method bodies, so
the public surface of `SharedUiWidgets` is unchanged.

## 3. Manager chrome surface treatment (and how it meets the theme)

`ViewerUiManager.DrawRegion` now wraps every region window (top bar, left sidebar, right
sidebar, bottom bar, status bar, options, minimap, chat) in
`SharedUiWidgets.PushSurfaceStyle()` / `PopSurfaceStyle()`, and `DrawDiagnosticsWindows` does the
same for the manager-owned **Log** and **Performance** windows. Every chrome region therefore
shares one surface treatment: `surface-1` background, `border` border, 4 px rounding, 8 px padding.

Theme interaction, stated plainly:

- `ThemesService` was **not** modified. It still applies the global palette at startup
  (`ViewerApp.cs:669`) and on every theme change, and it still owns text, frames, buttons,
  headers, tabs, menus, separators and popups.
- The token surface is pushed per region draw, so the shell's window background/border/rounding
  now come from the tokens. The manager does not re-assert token colours after the theme, and no
  code was added to fight the theme.
- The manager-owned **modal popups** (Settings, About, Keyboard Shortcuts, UI Reference) keep the
  theme's popup palette: they are dialogs, not chrome regions.
- Moving the theme itself onto the token palette (type scale, P9/T100) is a later phase and was
  not started.

## 4. Conversion decisions (per surface, with the judgement stated)

### Navigator (`NavigatorPanelService.Sidebars.cs`, `NavigatorPanelService.cs`)

1. `ImGui.SeparatorText("Export Map")` → `SharedUiWidgets.SectionTitle("Export Map")`. It stays
   **non-collapsible**: turning it into a collapsing header would have changed behaviour, which
   the P8 risk table forbids.
2. The hard-coded `PushStyleColor(ImGuiCol.Text, new Vector4(0.5f, 0.5f, 0.5f, 1f))` grey around
   the map row → `SharedUiWidgets.MutedSelectable(...)` (`UiTokens.TextMuted`). Double-click to
   load still works only for WDT-bearing maps, exactly as before.
3. `ImGui.TextColored(new Vector4(0f, 1f, 0f, 1f), "WDL preview ready…")` →
   `SharedUiWidgets.SuccessText(...)` (`UiTokens.Success`).
4. "No data source loaded" plain text → `SharedUiWidgets.DrawEmptyState("No data source loaded",
   "Use File > Open Game Folder to load MPQ archives, or 'Open WC3 Beta data' above.",
   "Open Game Folder...", <the same folder-input action the Workspace section already uses>)`.
   This is the one place where the empty state carries the action that fixes it.
5. Plain `ImGui.Button(...)` calls that the control inventory discovers — "Open Game Folder...",
   "Open File...", "Open Cartography", "Log", "Performance", "Open Selected", "Copy Path",
   "Use For Taxi Override", "Return To Last World" — now use `SharedUiWidgets.ActionButton(...)`
   with the **same label and the same full-size button**, so the P8 pass itself did not change
   the documented control set. (The later scanner extension grew the registry to **115**; see §7.)
6. `DrawAssetPathActions`: the "Copy Path##…" / "Load Asset##…" `SameLine` chain →
   `SharedUiWidgets.DrawButtonRow(...)`; the disabled "Load Asset" state is preserved.

### WorkbenchPanels (`WorkbenchPanelsService.cs`)

1. `ImGui.CollapsingHeader("Selected Object", flags)` →
   `SharedUiWidgets.SectionHeader("Selected Object", defaultOpen: defaultOpen, id: "SelectedObject")`.
   This is a **true section header**, so it is converted: it still collapses, still returns the
   same open/closed value to the caller, and still draws the same summary body.
2. The "Current context" two-line `TextDisabled` pair →
   `SharedUiWidgets.DrawEmptyState("Nothing selected", "Move the camera over a loaded ADT/MCNK, or
   select a model, world object, or PM4 surface.")`. No action is offered because this panel owns
   no action that creates a selection.
3. "Load a world to inspect it." / "Load a world to inspect PM4." / "Load a world to use taxi
   tools." → `SharedUiWidgets.DrawEmptyState("No world loaded", …)`. No action: loading a world
   is a Navigator action, not an Inspector/Scene-Tools action.
4. "Load Area POIs" / "Load AreaTriggers" → `SharedUiWidgets.ActionButton(...)` (labels kept so
   the registry entries survive).
5. **Not converted — deliberate:** `ImGui.TreeNode($"Area POI Details ({count})")`. Judgement: it
   is expandable **data** (a scrollable, selectable POI list with double-click navigation), not a
   section header; converting it to a collapsing section would change what the node is. It is the
   only raw ImGui tree/collapse call left in the five surfaces, and it is listed as a known,
   accepted exception.

### Chrome (`ViewerChromeService.Opacity.cs`)

1. "Object Transparency & Visibility", "WMO Buildings & Structures", "Collision Walls" and
   "M2 & MDX Doodads / Models" were `SharedUiWidgets.CompactStatus(...)` used as headings →
   `SharedUiWidgets.SectionTitle(...)`, so they now use the shared section style.
2. The three opacity button chains (WMO opacity, collision walls, M2/MDX) →
   `SharedUiWidgets.DrawButtonRow(...)`; the two hover tooltips moved into the row's per-button
   help. Spacing is 8 px, identical to the previous `ImGui.SameLine()` default in both shipped
   themes.
3. The Chrome surface had **no** hard-coded colours and no bespoke headers before this pass, so
   no other change was needed there.

### MainMenu (`MainMenuBarService.ViewerKeyBindings.cs`)

1. The "Keyboard Shortcuts" popup title and the per-context group titles (raw
   `ImGui.TextUnformatted`) → `SharedUiWidgets.SectionTitle(...)`. These are group headings, not
   data, so they use the shared section style.

### Verification of the five surfaces

A scan of the five manager-owned service directories for

returns **1 hit**: the deliberate "Area POI Details" tree node above. There is no other bespoke
