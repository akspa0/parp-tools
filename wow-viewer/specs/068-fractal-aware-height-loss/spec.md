# Feature Specification: Fractal-Aware Height Loss

**Feature Branch**: `068-fractal-aware-height-loss`

**Created**: 2026-06-20

**Status**: Draft

**Input**: User request: "add spectral loss and fractal dimension aux head to V21 loss for fractal terrain priors"

## Problem Statement

WoW terrain is generated by fractal processes (Perlin/Simplex noise, midpoint displacement, fractal Brownian motion). The current V21 height model learns terrain height from minimap + alpha + liquid + object inputs using only L1 + gradient + normal consistency losses. These pixel-space losses don't capture the *fractal statistics* of terrain — the power-law spectrum (P(f) ∝ 1/f^β) and multi-scale self-similarity that characterizes natural terrain.

The model must learn the *output* of a procedural fractal generator from 2D renderings, but has no explicit fractal prior. This leads to:
- Blurry large-scale features (mountains, valleys)
- Incorrect small-scale statistics (wrong roughness at shorelines, ridges)
- Spectral mismatch: predicted height lacks the 1/f^β power spectrum of real terrain

## Goal

Add two cheap, high-impact fractal-aware losses to the V21/V21c training:

1. **Spectral Loss** — match the radial power spectrum (1/f^β power law) of predicted height to ground truth in Fourier domain
2. **Fractal Dimension Auxiliary Head** — predict local fractal dimension (Hurst exponent) per 16×16 patch as auxiliary regression target

Both are O(N log N) via FFT, add <5% training time, and directly encode fractal terrain priors.

## Scope Boundaries

### In Scope
- Spectral loss term added to V21/V21c loss function
- Fractal dimension auxiliary head (16×16 regression) on V21 model
- CLI flags for spectral_weight and fractal_dim_weight
- Integration with existing V21/V21c tasks and V21 loss function

### Out of Scope
- Wavelet scattering transform input channels (future work)
- Full procedural generator inversion (different approach)
- Changes to V16.1 height model (separate task)
- Fractal parameter estimation from game files (separate research)

## User Scenarios & Testing

### User Story 1 — Spectral Loss Forces Correct Fractal Statistics (P1)

As a terrain model trainer, I want the spectral loss to penalize power-spectrum mismatch so the model learns the correct 1/f^β fractal statistics of terrain height.

**Independent Test**: Train V21c with `--spectral-weight 0.1`, verify that radial power spectrum of validation predictions matches ground truth power-law slope β within 10%.

**Acceptance Scenarios**:
1. **Given** V21c model with `--spectral-weight 0.1`, **When** training on curated tiles, **Then** radial power spectrum slope β of predictions is within 10% of ground truth β.
2. **Given** trained model, **When** evaluated on validation tiles, **Then** log-log power spectrum plot shows parallel lines for pred vs target.

---

### User Story 2 — Fractal Dimension Aux Head Learns Local Roughness (P1)

As a terrain model trainer, I want an auxiliary fractal dimension head that predicts local Hurst exponent H per 16×16 patch so the model explicitly represents local roughness.

**Independent Test**: Train V21 with `--fractal-dim-weight 0.05`, verify aux head predicts H ∈ [0.3, 0.7] matching variogram-estimated H on validation tiles.

**Acceptance Scenarios**:
1. **Given** V21 model with `--fractal-dim-weight 0.05`, **When** training completes, **Then** aux head outputs H ∈ [0.2, 0.8] on validation tiles.
2. **Given** validation tiles with known shoreline/ridge/flat regions, **Then** predicted H is lower at shorelines (rougher) and higher on flats (smoother).

---

### User Story 3 — Cheap Integration, No Training Slowdown (P2)

As a training operator, I want the fractal losses to add <5% wall-time per epoch so they don't slow down iteration.

**Independent Test**: Profile epoch time with `--spectral-weight 0.1 --fractal-dim-weight 0.05` vs baseline, confirm <5% overhead.

**Acceptance Scenarios**:

## Requirements

### Functional Requirements

- **FR-001**: Spectral loss computes radial power spectrum of `pred * train_mask` and `target * train_mask` via 2D FFT, computes log-log MSE between radial profiles.
- **FR-002**: Spectral loss weight controlled by `--spectral-weight` (default 0.1).
- **FR-003**: Fractal dimension aux head added to V21HeightModel: 16×16 regression head on bottleneck features → single scalar H per 16×16 patch.
- **FR-004**: Fractal dimension target computed per 16×16 patch from ground truth height via variogram/Hurst estimation.
- **FR-005**: Fractal dimension loss weight controlled by `--fractal-dim-weight` (default 0.05).
- **FR-006**: Both losses gated by `train_mask` (filtered objects + liquid masking).
- **FR-007**: CLI flags: `--spectral-weight` (default 0.1), `--fractal-dim-weight` (default 0.05).
- **FR-008**: Losses only active for V21/V21c tasks (not base height task).

### Key Entities

- **Spectral Loss**: log-log MSE between radial power spectra of pred vs target height (masked).
- **Fractal Dimension Head**: 16×16 regression head on V21 bottleneck → scalar H per patch.
- **Fractal Dimension Target**: local Hurst exponent H ∈ [0,1] per 16×16 patch from ground truth via variogram.

## Success Criteria

- **SC-001**: V21c with `--spectral-weight 0.1 --fractal-dim-weight 0.05` achieves val L1 < 0.65 (vs 0.69 baseline) within 30 epochs.
- **SC-002**: Spectral loss adds <5% epoch time (measured on 831 train tiles, batch 38).
- **SC-003**: Fractal dimension aux head predicts H ∈ [0.3, 0.7] with MAE < 0.1 vs variogram H on validation tiles.
- **SC-004**: Radial power spectrum slope β of predictions matches ground truth β within 10%.

## Assumptions

- Ground truth height_257 has correct fractal statistics (it's the game's procedural output).
- 16×16 patches are sufficient for local fractal dimension estimation (matches MCNK chunk size).
- FFT on 257×257 is fast enough (<5% overhead) with PyTorch FFT.
- Variogram-based Hurst estimation on 16×16 patches is stable enough for supervision.

## Dependencies & Constraints

- Requires PyTorch 1.7+ for `torch.fft.rfft2`.
- V21/V21c tasks only (controlled by task_name check).
- Fractal dimension target computed on-the-fly from batch `height_norm` (no new Zarr arrays).
- Must not break existing V21/V21c training when weights = 0 (default off).
